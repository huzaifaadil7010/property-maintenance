# Property Maintenance

A multi-tenant property maintenance platform that gives property owners, residents, and technicians one accountable workflow for reporting, assigning, completing, and verifying maintenance work.

## What is included

- Organization-scoped property, unit, resident, and technician management
- Separate owner, resident, and technician workspaces
- Maintenance requests with priorities, categories, status history, photos, and completion evidence
- Technician assignment and resident resolution confirmation or reopening
- Dashboard summaries, attention queues, notifications, and activity history
- Owner subscriptions, trials, saved payment methods, and Stripe webhook synchronization
- Password authentication, email verification, two-factor authentication, and passkeys
- Role and team-aware authorization with tenant-scoped data access

## Stack

- PHP 8.4 and Laravel 13
- Inertia.js 3, React 19, and TypeScript
- Tailwind CSS 4 and Radix UI primitives
- Vite 8 and Laravel Wayfinder
- SQLite by default; MySQL and PostgreSQL are supported by Laravel configuration
- Laravel Fortify and Passkeys
- Laravel Cashier with Stripe
- Spatie Permission, Laravel Data, Activitylog, and Media Library
- Pest 4, PHPUnit, Laravel Pint, ESLint, Prettier, and TypeScript

## Requirements

Install these before starting:

- Git
- PHP 8.4 with SQLite, PDO, BCMath, cURL, DOM/XML, Fileinfo, GD or Imagick, Intl, Mbstring, and OpenSSL extensions
- Composer 2
- Node.js 22 or newer and npm
- Stripe CLI only if you want to test subscriptions and webhooks locally

## Quick start

```bash
git clone https://github.com/huzaifaadil7010/property-maintenance.git
cd property-maintenance
composer setup
composer dev
```

The setup command installs PHP and JavaScript dependencies, creates `.env` and the SQLite database, generates the application key, migrates and seeds the database, creates the public storage link, and builds the frontend.

Open [http://localhost:8000](http://localhost:8000). `composer dev` runs the Laravel server, database queue worker, application log viewer, and Vite development server together. Stop all processes with `Ctrl+C`.

If `public/storage` already exists, `php artisan storage:link` may report that the link is already present; no further action is needed.

## Manual installation

Use these steps when you want to control each part of setup:

```bash
git clone https://github.com/huzaifaadil7010/property-maintenance.git
cd property-maintenance

composer install
cp .env.example .env
touch database/database.sqlite
php artisan key:generate
php artisan migrate --seed
php artisan storage:link

npm install
npm run build
composer dev
```

For MySQL or PostgreSQL, create the database first and replace the `DB_*` values in `.env`; the SQLite file is then unnecessary.

## Stripe test-mode setup

The landing page and authentication flows work without Stripe credentials. Billing and access to subscribed dashboards require a Stripe test account.

1. In Stripe test mode, create a recurring monthly Price.
2. Add the test publishable key, secret key, and Price ID to `.env`:

```dotenv
STRIPE_KEY=pk_test_...
STRIPE_SECRET=sk_test_...
STRIPE_OPERATIONS_PRICE_ID=price_...
CASHIER_CURRENCY=usd
CASHIER_CURRENCY_LOCALE=en_US
```

3. Reseed the plan after changing the Price ID:

```bash
php artisan db:seed --class=PlanSeeder
```

4. In another terminal, forward Stripe test events to Cashier:

```bash
stripe login
stripe listen --forward-to http://localhost:8000/stripe/webhook
```

5. Copy the `whsec_...` value printed by the Stripe CLI into `.env` as `STRIPE_WEBHOOK_SECRET`, then restart `composer dev`.

For a successful test payment, use Stripe's test card `4242 4242 4242 4242`, any future expiry date, and any valid CVC. The webhook secret generated by the Stripe CLI is session-specific and differs from a Stripe Dashboard endpoint secret.

## Email, queues, and uploaded media

Local email uses the `log` mailer, so messages are written to `storage/logs/laravel.log`. Account invitations and maintenance notifications are queued. Keep `composer dev` running, or run a worker separately:

```bash
php artisan queue:work
```

Maintenance images use the public media disk. The `php artisan storage:link` step makes them available from the browser.

## Production notes

Before deploying, set `APP_ENV=production`, `APP_DEBUG=false`, a correct HTTPS `APP_URL`, production database and mail credentials, durable queue/cache drivers, a production media disk, and live Stripe credentials. Run a persistent queue worker and configure the Stripe Dashboard webhook endpoint for `/stripe/webhook`.

Do not commit `.env`, Stripe secrets, database files, generated build output, uploaded media, or other credentials. The repository's `.gitignore` already excludes the common local versions of these files.
